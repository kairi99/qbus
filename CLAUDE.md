# QBus

Arcade "Crazy Taxi"-style game: drive a reckless Quito bus, pick up passengers at stops.
Browser game: Three.js (rendering) + Rapier (`@dimforge/rapier3d-compat`, physics), TypeScript, Vite.
Full roadmap (milestones M0–M6): `~/.claude/plans/pasted-content-id-88c6-i-want-synchronous-wren.md`.

## Commands
Node comes from nvm: run `. ~/.nvm/nvm.sh` first in non-login shells.
- `npm run dev`: dev server on http://localhost:5173
- `npm test`: Vitest unit tests (`tests/`), physics runs headless in Node
- `npm run test:underpass`: the bridge/underpass harness, slow physics suites included (`tests/underpass/README.md`)
- `npm run e2e`: Playwright smoke test (`e2e/`), writes screenshots to `e2e/screenshots/`
- `npm run build`: typecheck + production build
- `npx tsx tools/fetch-osm.ts [zone] [osm|routes|stations|areas]`: download a zone from Overpass into `data/raw/` (`<zone>.osm.json`, `.routes.json`, `.stations.json`, `.areas.json`; all by default; servers are flaky, mirrors are tried in order)
- `npx tsx tools/build-city.ts [zone]`: raw OSM + Copernicus DEM → `data/cities/<zone>.json` (zones live in `tools/zones.ts`)
  The DEM tile is not in git (41 MB): `curl -o data/raw/copernicus-S01-W079.tif https://copernicus-dem-30m.s3.amazonaws.com/Copernicus_DSM_COG_10_S01_00_W079_00_DEM/Copernicus_DSM_COG_10_S01_00_W079_00_DEM.tif`

## Conventions
- Chassis/physics space: +X forward, +Y up, +Z right. Heading 0 = facing +X.
- Physics code (`src/vehicle/bus.ts`, `src/physics/`) must not import three.js so it stays testable in Node.
- All driving feel lives in `data/buses/*.json` (buses, and the AE86 car with `kind: "car"`, free roam only); tune there, not in code (including `nitro`: extra acceleration and how far past top speed it pushes). The nitro tank rules (1.5 s full burn, a burst needs half a tank, refilled only by drifting, close calls and running red lights, plus in a race the perfect launch and the pickups on the road) are gameplay, in `src/gameplay/nitro.ts`.
- UI text in Spanish (Quito slang welcome); code and comments in English.
- Playwright uses a manually downloaded Chrome at `~/.cache/qbus-chrome/` (the CDN install times out here) with SwiftShader WebGL.
- `window.__qbus` exposes game state in dev builds for e2e tests.
- City data, terrain, the road graph, and OSM import (bridges/underpasses, rapid transit, map edge, campus walls, far view): see `src/world/CLAUDE.md`.
- Settings (`src/menu/settings.ts`) carry a version: when a default changes, bump it and decide what an old saved value means (version 2: a saved 1.3 hills was the old default, so it becomes the new one, "Reales").
- Menus (`src/menu/`): `/` shows the title/setup menu; the game starts only with `?play=1` (from the menu) or a direct `?city=`/`?seed=`. Choices and settings live in localStorage (`settings.ts`). Buses are listed in `src/vehicle/buses.ts`; every preset must pass `tests/bus.test.ts`. Routes come from `routesFor(city)` (`src/gameplay/routes.ts`).
- Navigation (`src/gameplay/navigation.ts`): Dijkstra over the directed lane graph, so guidance and route building respect one-way streets. `new Navigator(graph, vehicle = 'general', generalCost = 1)`: ordinary vehicles never use a busway edge (`Road.access === 'brt'`, see `src/world/CLAUDE.md`), `'brt'` vehicles may (rapid-transit routes use it, with `BRT_GENERAL_COST` = 3 so they follow the busway whenever there is one; route/leg lengths are real meters via `pathMeters`, not the weighted cost). BRT lines (Trolebús C4, which also stands for C1 whose stations are the same, Ecovía E1/E3; MetroBus has only two stations in the zone, 4 stops, too few for a route) start their loop at the first stop served from a busway lane, and `startPose` snaps with `vehicle: 'brt'` so the bus starts on the busway; ordinary routes and free roam never use or are guided onto one. The in-game arrow and minimap follow the legal path (`session.path`), never a straight line to the stop. Routes only keep stops whose legs can be driven legally without big detours. The menu map draws each leg's legal path (`routePaths`), and the bus starts on the lane leading into the first stop, facing it (`startPose`, via `Navigator.behind`). Where roads pass over each other, everything is located at a height: `locate(p, heading, y)` (stops at street level, the bus at `BusPhysics.roadHeight()`, its wheels' contact height), paths carry each point's lift so the arrow (`guidePoint(..., lift)`) never follows the street over the bus's underpass, and the R reset (`snapToRoad(..., y, { clear: vehicleClearance(world, body), length })`) stays on the bus's level and slides to a spot where the bus box clears the static world, pitched to the road.
- Map data is ODbL: keep the on-screen OpenStreetMap credit (`city.attribution`).
- Names and credits: real streets, places and transit systems (Trolebús, Ecovía, Metro) appear as plain text only; real companies never do. Bus operators get a look-alike name at import (`src/world/osm/operators.ts`, "Catar" → "Katar"; add any new operator there, `tests/operators.test.ts` checks none leaks into the city data), the car is the "Toyoya Sprinta Trueno AE86", Metro totems carry our own pictogram (not the city's "M" logo), and shop signs are invented. The menu's "Créditos" screen holds the OSM/ODbL, full Copernicus and sound/music credits and the non-affiliation notice: update it when adding data, sounds or names.
- Headless Chrome renders with software WebGL (~5–20 fps), which slows the simulation (frame dt is capped at 0.1 s). In e2e, poll for conditions (`expect.poll`) rather than fixed sleeps.
- BRT buses and menu: picking a Trolebús/Ecovía route in the menu selects the articulated bus (`BRT_BUS`, `busForRoute` in `menu.ts`: unless the player picked another bus by hand for BRT routes; going back to an ordinary route restores the bus it replaced; saved settings are not overridden at load); the placard says "Carril exclusivo · Recomendado: Articulado". Any bus may drive any route, and a link to a BRT route without `?bus=` takes the articulated one. A non-BRT vehicle on a busway is not punished: the HUD street label already reads "Carril exclusivo" there. The tutorial adds a line on BRT routes.
- Traffic/pedestrians: ambient articulated buses (`BRT_KIND`, 18 m, 3 instanced meshes' worth in `trafficView.ts`: two box sections + bellows) ride the busway lanes only (`TrafficSim` option `brt`, `brtBusCount`: 1 per ~1.2 km of busway, 1 to 4, 0 without a busway; outside `setBudget`); they only go straight on (a turn would swing the rigid 18 m box over the street beside), stop 5 s at a station (`stations`: stop zones beside a busway edge facing its way), keep a junction claimed until their tail clears it (`tail`), ignore an oncoming busway bus (it's in the other lane) and share a junction with straight movements along their own axis (`straight`/`parallel` in `canEnter`: the avenue beside the busway, the oncoming bus) only where the two paths stay a bus and a buseta apart for 20 m out (`clearOf`; a busway leaving a junction a lane from the avenue's near lane doesn't share it), or two buses meeting nose to nose wait on each other for good, claim the junctions their busway runs through without meeting them (`Crossing`: OSM draws the Ecovía across a side street's junction with 6 de Diciembre with no shared node; the bus stops short until nothing but straight traffic alongside is in it, holds it until its tail is out, and cars wait for it there like for any car in the junction), obey lights, wait out of sight at a busway's end and recycle like cars, and become wrecks when hit. Ordinary cars never use busways. `traffic.ts` and `pedestrians.ts` are pure sims (unit-tested for overlaps and gridlock on both cities); `trafficBodies.ts` makes Rapier bodies chase the sim poses (height and pitch from the terrain) and releases a car to free physics when the bus hits it. Junctions admit one incoming edge at a time; there is no forced entry (stuck cars are recycled instead). A car never claims a junction while queued behind a car on the same approach that hasn't (one in the next lane whose path merges into ours: with our claim it may not go in, and we can't pass it), and a car held back by a short exit's next junction (`after.len` < 25 m) claims priority there too after `PRIORITY_WAIT`, or a busy stream through it starves the short exit's feeders (the Queseras tunnel link behind Queseras' 16 m). Traffic lights (`gameplay/trafficLights.ts`, pure, tested; `TrafficLights` from `city.signals` and the road graph): a junction with a signal at its level on its paved area or up to 15 m out an approach is lit; its incoming edges are grouped into phases by approach axis (opposite approaches together), each phase green 14 s (10 s with 3+ phases), amber 3 s, then 2 s all red; per-junction offsets from position, but junctions within 60 m share timing and give the widest road the first phase (a divided avenue's two crossings). Everything is a function of the traffic's clock (`TrafficSim.time`). Cars stop with the bumper at the stop line (4 m before the edge end, behind the zebra) on red, and on amber if they can at 3.5 m/s²; a car waiting at a light, or queued behind one that is (`Car.held`), neither claims junction priority nor counts toward `STUCK_WAIT`, and a priority claim lapses while its approach isn't green. Pedestrians at a lit crossing wait at the curb for the crossed approach's red. `world/signalBuilder.ts` draws a pole on the right curb at each stop line with an arm over the incoming lanes and a three-lamp head (static tiles, solid pole), the lamps as one instanced mesh whose instance colors change with the lights (plus an additive glow mesh after dark: no real lights), and a stop line. Pedestrians walk sidewalk strips derived from the road graph and have no colliders by design. Traffic in its lane is in collision group TRAFFIC and ignores the STATIC world (`markStatic` in `physics/world.ts`, called at the end of `buildCity`): the sim keeps cars on the road, so seams in ramps or walls can't knock them off; a car hit by the bus becomes a wreck that collides with everything (`tests/interchanges.test.ts` runs traffic through both interchanges). Cars ride the road's own surface (`laneSurface`: `surfaceY`, and near bridges/cuts the solid surface under them by a short STATIC ray), placed on it from the first frame. Obstacles carry a `lift` (height off the ground): things on another level (a street over an underpass) don't hold a car up, and pedestrians keep off the edges of open cuts.
- Passengers get on and off when the bus is in the stop zone below 25 km/h (`STOP_SPEED` in `routeGame.ts`): a Quito bus barely stops.
- Scores and missions (route shifts only, pure modules): `gameplay/stars.ts` sets each route's 1–3 star money targets from model drivers (`STAR_TIERS`: door-to-door pace 10/14/16.5 m/s along the legal legs, `routeLegs`, through the real `RouteGame` rules, plus trick money of 0/0.75/5 cents per second of the shift (the autopilot runs every red it meets) and 0/1/2 average mission bonuses), so routes with long legs or detours ask less fare money. 1★ = a steady clean shift, 2★ = quick with some tricks and a mission, 3★ = expert (beyond the autopilot). The paces come from `tools/sim-shift.ts` (an autopilot driving the real physics bus through shifts: casual/decent/expert); `tests/stars.test.ts` pins its earnings so the autopilot never gets 3★ (except on Belavista 002's long straight avenues); `tools/star-targets.ts` prints every route's targets. Targets show on the start prompt, as a meter beside the money (stars won + money for the next), ticked on the results screen and on each menu placard. `gameplay/records.ts` keeps a top 5 per `zone/route` (any bus; the bus is noted), best stars, and mission completion counts in localStorage `qbus.records` (versioned; corrupt data is dropped, never thrown; version 1 records keep their money but lose their stars, earned against the old easy targets; the placards and top 5 rate saved money against today's targets). `gameplay/missions.ts` is the pool of optional objectives (3 random per shift, a cash bonus each), fed `MissionEvent`s by `GameSession`; only build missions on events the game reliably detects. Running a red (`RedLightRunner`: the bus's front bumper crossing a stop line into the junction while that approach is red, amber doesn't count, at the light's level, once per junction and cycle; route shifts and free roam) is the trick "¡Pasó en rojo!" (20 cents, joins combos), refills a quarter tank of nitro, honks the drivers, and counts for the "Pásate 3 rojos" mission. If scoring, fares, time bonuses or missions change, rerun `tools/sim-shift.ts` and retune `STAR_TIERS`.
- Free roam (`?play=1&mode=free&city=&bus=`): `GameSession` with `route: null` (`game` is null): traffic, people and nitro, but no stops, clock, fares or trick money; starts at `freeStartPose`. The menu's "Paseo libre" mode offers `VEHICLES` (buses + `CARS`); a route shift always uses a bus. Cars have their own model (`vehicle/carBody.ts`) and a `cockpit.seat` in the preset.
- Articulated bus (`data/buses/articulado.json`, `preset.articulated`, "Articulado BRT", 18.4 m, any route and free roam; the gusanito is the same machinery with 4 rear sections): `BusPhysics` makes two Rapier bodies, each with its own raycast vehicle (front section: steered axle + driven middle axle; rear section: one trailing axle), hinged by a ball joint at the turntable with contacts between the sections off; the joint's motors (set through the raw joint set, since rapier3d-compat 0.20 gives a spherical joint no JS motor API) hold the roll and push back past `yawLimitDeg`. Chosen over a kinematic trailer by `tools/spike-articulated.ts` (the trailer drives through walls when reversing, 3.4 m deep). `body` is the front section; the rest of the game must go through `bus.position()` (middle of the whole vehicle: stops, traffic, R reset, minimap), `bus.nose()`, `bus.sections()` (one traffic obstacle box per section), `bus.colliders`/`bus.bodies` (hits on either section make a car a wreck; near-miss rays leave from both; the reset places both in line, `Spawn` x/z is the middle of the vehicle), `bus.frontLength` (cockpit seat and doors are in the front section), `bus.wheelCount`. Section ends are chamfered (`bevel`): a plain 9 m box high-centers where a ramp flattens out. Handbrake drifts are arcade-assisted (`driftLock` freezes the turntable, `driftYawRate` pushes the yaw and fades near `drift.maxAngleDeg`, `driftFrontGrip` loosens the front tires) so front-section slip passes 20° for >1 s and scores; `tools/sim-shift.ts` (`BUS=articulado`) steers by `nose()`; `position()`/`nose()` take an `out` object for per-frame callers. `tests/bus.test.ts` (articulated block), `tests/articulated.city.test.ts`, the underpass harness (`DRIVE.RUNS`; known failure `Q1A`) cover it. The model has doors on both sides (left for BRT platforms) and a bellows.
- El Gusanito (`data/buses/gusanito.json`, any route and free roam, never traffic): the fairground "worm" train, a worm-faced head car pulling 4 open wagons under striped canopies (`articulated.sections` = 4: `BusPhysics.rears` is a chain, each wagon hinged to the one ahead with one trailing axle; `bendAt(i)` per turntable, `bus.rear` is the first). Its sections share a collision bit of their own (`GROUP.TRAIN << k`, one per train, `physics/world.ts`), which they filter out (another gusanito, a race rival, is solid), and its wheel rays skip it: on a tight bend a wagon swings into the box of the one two ahead. A train folds in reverse, so `reverseLock` pulls the turntables straight while backing up (it reverses like one rigid bus); no `driftLock` (the head car drifts and the wagons whip behind), and a stiffer yaw limit (`yawLimitStiffness`: light wagons swing past it in a crash). Model in `vehicle/gusanitoBody.ts` (eyes, lips, antennae, riders, LED strips that glow at night, a spiral tail), cockpit without the windshield and eyes; riders board at the first wagon (`passengersView`); it gets the car's engine sound and no door hiss (`isTrain`).
- Rain (`gameplay/weather.ts`, pure, tested; Ajustes "Lluvia": `random` (default: a shower starts 25–200 s in, then showers of random strength and dry spells), `always`, `off`; `?rain=0|1|2` overrides: never, raining, a downpour): `Weather.state` = `rain` (0..1), `wet` (the road: wets fast, dries over ~90 s) and `flood` (m: only rain over `DOWNPOUR` 0.7 fills the underpasses, up to 0.75 m, draining after). Grip: `bus.grip = gripFor(wet)`; a wet road caps the tires' `frictionSlip` at the preset's `wet: { front, rear }` (tuned per vehicle with `tools/wet-grip.ts` to slide 10–16° at full lock at speed, 3–8° dry; the articulado never reaches the limit and only brakes longer) and brakes stop 30% less hard. Rapier's raycast tires cancel all sideways speed each step, so scaling their correction or friction proportionally does nothing: only an absolute cap under what a turn needs slides. Floods: `world/floods.ts` finds each underpass's basin (cut roads whose floors meet at about the same height share one) and draws its water as one opaque mesh raised by the flood depth; `waterDepth` sets `bus.wade`, whose drag (and lost grip past 0.15 m) holds a bus to a crawl (nitro still pushes), with spray off the wheels (`BusModel.setSpray`); traffic crawls (3.5 m/s) through flooded lanes (`TrafficSim.slowEdges`) and drives 15% slower on a wet road (`speedScale`). `world/rain.ts` (`RainView`): streaks around the camera moved in the vertex shader (one draw call), faded out under a roof (an upward static ray from the camera), sky/fog/lights overcast (city and backdrop), lightning and thunder in a downpour; synthesized rain, splash and thunder sounds (`BusAudio.weather`/`thunder`, `LEVELS`). A passenger and a popup announce the rain and the floods (`session.weatherNews`).
- Race tracks (`city.race`, `world/track.ts`): a stretch of a real mountain highway imported as a zone with `track` in `tools/zones.ts` (`fetch-osm.ts` gets only that highway's ways, plus `<zone>.scenery.json`: buildings, rivers/streams, pipelines, roadside businesses; `build-city.ts` calls `importTrack`, `world/osm/track.ts`). First one: "Paso de la Muerte", `papallacta` (E20 from Papallacta toward Cuyuja, 4.8 km raced). The road is `city.roads[0]` with its own heights (`Road.surface`, used by `roadProfiles`), drawn and solid as a deck of its own (`world/trackBuilder.ts`, one trimesh collider per 60 m): the terrain is carved under it only as much as it pokes through (`fitUnderDeck`, sampled on the asphalt; lowering whole 8 m triangles left stair-stepped shelves), cut into the slope uphill, and downhill a fill bank (`FILL`) then the valley side steepened near the road (`DEEPEN`); a draped bank strip along the edge (`fillBanks`) hides the 8 m grid's sawtooth. `race.rails`/`race.drops`: solid guardrails along about three quarters of the drops, the rest open (never near the start or finish), roadside shrines (crosses, capillitas) at some open drops; chevrons on tight bends, SALIDA/META gantries, the town's name and "ZONA DE NEBLINA" signs. Scenery from OSM (`race.scenery`): rivers carved into the valley floor (water never rising downstream), the oil pipelines on stands beside the road (broken where they pass under it), Papallacta's buildings (block walls, tin roofs) and the roadside restaurants (mapped only as points: a small building of their own, set back and square to the road), signed by trade only ("TRUCHAS", never a real name). Instanced trees/shrubs/rocks (`plantSpots`: never within `PLANT_CLEAR` of any leg of the road, searched along the whole track, nor in rivers, buildings or on pipes; trunks near the road solid). Mist (`world/mist.ts`, one instanced billboard draw call): cloud banks on the valley sides, two misty stretches over the road, cloud banks over the far ridges and volcanoes in the backdrop. No traffic or pedestrians on a track; a long light haze in both passes (`TRACK_FOG`), the far view in mountain colors without Quito's lights; hills scale is ignored. `locateOnTrack(t, p, hint?, reach?)` counts `p.y` when given (a hairpin's other leg 40 m off but 80 m up isn't the road under a bus; callers search the whole track when the near search lands more than 25 m off). Going over the edge (`gameplay/fallWatch.ts`, pure): "¡Al barranco!" and back on the road 25 m behind. `tests/track.test.ts`, `e2e/track.spec.ts`.
- Race mode (the menu's "Carrera": track card with the best time, the track's map and profile, rivals 1–3, what they drive, skill, traffic; `Settings.race`; `?play=1&mode=race&city=papallacta&rivals=1..3&rivalBus=mixed|same|<vehicle id>&skill=easy|normal|hard&traffic=1`, any vehicle): `gameplay/raceField.ts` (pure) has the crews (`CREWS`: invented companies "Chulla Vida", "Ñaño Veloz", "Trans Guambra", each a livery on whatever preset it drives), `rivalVehicles` (mixed: each rival a different vehicle and none the player's while there are others; the same as the player; or one vehicle for all) and `gridSlots(track, lengths)` (alternate lanes, each lane's vehicles one behind the other with room, so four 19.6 m gusanitos fit behind the line). `gameplay/raceSession.ts` (`RaceSession`, three.js) puts the rivals on the grid in front and the player at the back (the session's `start`), all held still (`DriveInput.parked`: full brakes, every wheel) through the grid wait and 3-2-1 (`gameplay/raceGame.ts`, pure: phases, progress past the start line by each front axle, places, finish; when the player finishes, the others get a time from their pace +3%, shown "≈"). On the grid the engine revs freely (`gameplay/launch.ts`, pure: `LaunchRev`, the audio's `rev`) and at GO the needle's place grades the start (`LAUNCH_EFFECT`: the green window is perfect, a boost for 1.2 s and a quarter tank of nitro (`Nitro.bonus`); either side of it good; under it the engine bogs, past it the tires spin); rivals roll theirs by skill (`aiGrade`). Rivals drive with `RaceDriver` (`gameplay/raceDriver.ts`, pure: pure pursuit at its `lane` + a speed profile from the bends, planned from the vehicle's own limits (`vehicleLimits`: top speed, top speed with nitro, and the cornering/braking it really manages dry and soaked, `BusPreset.race`, measured per vehicle with `tools/sim-race.ts` (`CORNER=`, `BRAKE=`, `WET=1`, `PACE=1.07`: the largest that finish clean, with a margin; buses never lose grip dry, so their dry values are where the time stops improving) and blended by how wet the road is (`driver.wet`)); `SKILLS` are shares of those limits (hard: all of them, nitro on every straight even past top speed, never easing off when ahead, passing on less clear road; normal 80–90%, easy 60–72%, no nitro), a light rubber band to the player (its push only on the straights: the bends are at the grip's limit), `limit` to follow a car it can't pass, `needsRescue` after 8 s without progress: put back on the road and held `RESET_WAIT` like the player's R); `chooseLane` (pure, tested) picks the lane: the other half of the road to pass a racer or a slower car close ahead, only with no oncoming car within 140 m (a car counts until it's behind our tail, so a pass never cuts back in on it; caught alongside with one close, it drops back), the right half with traffic on (well over to the right to meet an oncoming car). They fall and respawn like the player, show on the minimap (`MiniMap.update(..., others)`), and are heard: `BusAudio.rivals` plays each one's engine (the player's recordings, diesel or petrol) through its own `PannerNode` from where it is, the listener at the camera, `LEVELS.rivalEngine` under the player's own. R in a race (only once racing) puts the bus back in its lane where it was on the track and holds it `RESET_WAIT` (3 s) with a countdown on screen (`RaceSession.playerReset`), so R is no shortcut out of a crash. Nitro pickups (`gameplay/pickups.ts`, pure: `TrackData.pickups`, a pair across the road every 480 m; a racer's whole length over one between two frames takes it, half a tank, back after 8 s; rivals take them too) drawn by `pickupView.ts` (blue canisters with an orange ring, floating and spinning, two instanced draw calls), with a chime. Traffic on a track (`traffic=1`, `TRACK_TRAFFIC` (6) cars, `SessionDeps.trackTraffic`; free roam on a track too): the city's `TrafficSim` with `keep` (cars never placed, nor driving, within 250 m past the start line: one heading for the grid is recycled out of sight or stops short) and `uturns: false` (off the road's ends instead), all in the bubble around the player (always some about, none far off costing time or holding up rivals nobody sees); rivals meet them there (`GameSession.racers`: obstacles for the cars, and they wreck the ones they hit). `tools/sim-race.ts [zone] [bus] [skill] traffic` runs the AI through traffic (cars hit, time following). `ui/raceHud.ts`: route, place and time, the countdown, the tachometer with the green window (gone after GO), a progress strip, the results card; best times in localStorage `qbus.raceRecords` (`gameplay/raceRecords.ts`). `tools/sim-race.ts` times the AI per bus and skill; `tests/race.test.ts`, `tests/track.test.ts` (AI buses finish, two together), `e2e/race.spec.ts`. A sleeping bus reports speed 0 (`BusPhysics.speed`: the controller keeps a stale value).
- Chase camera (`camera/cameraRig.ts`): with `CameraRig.obstacles` (`physics/cameraObstacles.ts`, ray casts against fixed colliders, small solids and the invisible map-edge box ignored) it comes down under a roof or deck over the bus and pulls in in front of anything solid between it and the bus; it pulls in at once and eases back out (no per-frame allocations).
- Tutorial (`ui/tutorial.ts`): a how-to-play card (2–3 pages: the job, free roam or the race (launch, pickups, ravines, the R wait, traffic if on), nitro and tricks, controls for keys or touch, pad line if one is connected) every time a shift, free roam or race starts (a race's grid waits for it). Its numbers come from the gameplay constants (`STOP_SPEED`, `START_TIME`, nitro, combo, `LAUNCH_EFFECT`, `PICKUP_FILL`, `RESET_WAIT`), so keep the text in step if the rules change. While open it takes the keyboard (capture listener ahead of `Input`) and `main.ts` holds the bus still, so the clock (first throttle) can't start; restarts don't reopen it. Off with "No mostrar otra vez" or Ajustes (`settings.tutorial`); e2e tests that don't care load with `?tutorial=0`.
- Driver's view (`setCockpitView`) hides the whole exterior (both sections of an articulated bus) and shows `cockpit` parts only (the front section's): they must close the cabin below the windows and join pillars to the roof, since the view widens with speed and nitro and any gap shows the road (`busCockpit`, `carCockpit`).
- Phones/tablets (`(pointer: coarse)`): `ui/touchControls.ts` draws on-screen controls that write `Input.touch` (left thumb steers relative to where it lands, right thumb pedals/nitro/handbrake, small buttons send `Input.press` actions); `body.touch` CSS moves the HUD out of the thumbs' way and hides key hints (`.keys-only`/`.touch-only`). `e2e/mobile.spec.ts` drives on an emulated phone. iPhone Safari ignores `user-scalable=no` and has no fullscreen API: `stopBrowserGestures` cancels touches on the controls and pinches (two thumbs look like one) and undoes any zoom that slips through; the canvas is sized from its own box (a `ResizeObserver`), never `100vw/100vh`; HUD and controls keep clear of the notch with `env(safe-area-inset-*)`; `public/manifest.webmanifest` makes "Add to Home Screen" open full screen and sideways.
- Sound (`src/core/audio.ts`, pure parts in `src/core/soundModel.ts`, tested): recordings in `public/sounds/` (mono MP3, fetched by relative URL after the first gesture; synth stand-ins if one fails). Buses: diesel idle + on-load loops pitched by a fake gearbox and crossfaded by RPM, a faint turbo whine under load, air brakes (release, hard-stop hiss, dryer purge at a long stop), truck horn, stop-request buzzer ("timbre") + door hiss at stops; the car (`kind: "car"`) gets a petrol idle + buzz and a car horn. Mix: files are normalized to -18 LUFS and every gain lives in `LEVELS` (`soundModel.ts`, tested: engine louder with throttle and in the bus than the car, one-shots a few dB over the cruising engine); the master feeds a gentle compressor. Re-measure with ffmpeg `ebur128` when adding a file. The menu has its own small synthesized UI sounds (`src/menu/menuSounds.ts`, no files, no three.js; pure parts in `menuSoundModel.ts`, tested): delegated on the menu root, hover/focus ticks (rate-limited), stop bell for cards, ticket punch + coin for routes, horn toot + air brake on ¡Arranca! (navigation waits `START_DELAY_MS` for it), back blip, setting clicks and a slider preview at the new volume; gains in `MENU_LEVELS`, under the game's one-shots, at the same 0.35 x volume master. Its context dies with the page when a shift starts. Only CC0 sounds so far; list every file's source/author/license in `public/sounds/CREDITS.md`, and a CC-BY one also needs an on-screen credit next to the OSM one.
- Radio (`src/core/radio.ts`, pure parts in `src/core/radioStations.ts`, tested): "Apagado" plus three stations, each looping a playlist of original songs (two each) from `public/music/` (CC0, `CREDITS.md`). `M` / pad X / the 📻 touch button tune the next station (with static and a `RadioToast` card naming the station and song); the last one tuned is saved as `settings.radio` (the starting station), next to `musicVolume` in Ajustes. Stations are "live": the broadcast is the playlist back to back, and tuning in starts at `onAirAt(session clock + station offset)` (which song, how far in), computed from each song's `duration` in the station data (a test checks it against the MP3 sizes: update it when re-rendering). A song is fetched only when needed (never on the menu) and only the song on air stays decoded; 12 s before it ends the station's next song is fetched, decoded and queued to start gaplessly, and a small card names it. The radio has its own gain and cabin low-pass straight to the destination (not through `BusAudio`'s master/compressor), ducked and muffled while paused. The songs are synthesized from code: `python3 tools/music/render.py` (needs `pip install -r tools/music/requirements.txt`); compositions, genre research and the mix analysis are in `tools/music/` (`README.md`). Keep them original (no existing melodies), different from the station's other songs, and all the MP3s under ~6 MB (64 kbps / 32 kHz; `tests/radio.test.ts` checks the budget).
- Performance: `index.html` loads `src/boot.ts` (menu, no three.js/Rapier); the game (`main.ts`) is its own chunk, fetched in parallel with the city JSON and prefetched from the menu, and three/Rapier get their own cached chunks (`vite.config.ts`). Draw calls matter more than triangles: build static scenery into merged `ChunkedMeshBuilder` tiles, never one mesh per object (`build(material, { merge, shadows })` draws blocks of tiles but lets the shadow pass cull per tile). Vehicle models are built from many boxes but drawn merged: `BusModel` runs `vehicle/mergeParts.ts` over each rigid section, the cockpit and each wheel (one mesh per shading kind, each part's color baked into vertex colors; moving parts, textured signs and the flames stay apart; `tests/mergeParts.test.ts` checks the triangles and colors are unchanged): a bus is 7 draws (it was 23), the gusanito 22 (299), which took a 3-rival race from ~860 draw calls to ~180. Most of a track's remaining triangles are its terrain (8 m grid out to the 3 km camera far): a coarser far LOD would let the terrain poke through the distant road deck (fitted to the 8 m grid), so there is none. Per-frame code allocates nothing it can reuse (scratch vectors/matrices as fields), and per-frame HUD writes go through `ui/dom.ts` (only on change). Measure with `npx tsx tools/perf-city.ts` (build time, meshes in view) and `QBUS_PERF=<tag> QBUS_PORT=<port> npx playwright test perf` (draw calls, triangles, frame JS ms in `__qbus.perf`, fixed-view screenshots to diff between runs). `npx tsx tools/perf-physics.ts [bus] [cars] [seconds]` times the headless sim per physics step in Node (Rapier step, bus controller, traffic AI, car bodies; about 0.8 ms/step with 40 cars, so on weak machines the GPU, not JS, is the bottleneck: in the browser under software GL the same numbers are inflated by contention). Adaptive quality (`core/adaptiveQuality.ts`, pure, tested; wired in `main.ts`): if the smoothed fps stays under 38 for 2 s the canvas pixel ratio steps down (levels 1, 0.85, 0.72, 0.6 of the usual cap), and if even the lowest level stays under 28 fps the shadow map drops to 1024; it steps back up after 10 s over 57 fps unless that level just failed. Each step down is judged after 3 s: if the smoothed fps did not rise by 10% (`MIN_GAIN`: a 30 Hz display, battery-saver cap or CPU-bound machine) the step is undone and stepping down (and shrinking shadows) is disabled for the session. Machines that hold 60 fps never leave level 0. Off under automation (`navigator.webdriver`) unless `?adaptive=1`, and off with `?adaptive=0` (`e2e/adaptive.spec.ts`). Props (`PropSystem`) only visit Rapier's awake bodies (`forEachActiveRigidBody`), never the ~2000 sleeping ones; the underpass ground patch is built in 120 m tiles so it culls (it was one always-drawn mesh of 114k triangles); the street name and the traffic obstacle list are not rebuilt every frame/step.
