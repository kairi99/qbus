# QBus

Arcade "Crazy Taxi"-style game: drive reckless Quito bus, pick up passengers at stops.
Browser game: Three.js (rendering) + Rapier (`@dimforge/rapier3d-compat`, physics), TypeScript, Vite.
Full roadmap (M0–M6): `~/.claude/plans/pasted-content-id-88c6-i-want-synchronous-wren.md`.

## Commands
Node from nvm: run `. ~/.nvm/nvm.sh` first in non-login shells.
- `npm run dev`: dev server on http://localhost:5173
- `npm test`: Vitest unit tests (`tests/`), physics headless in Node
- `npm run test:underpass`: bridge/underpass harness, slow physics suites included (`tests/underpass/README.md`)
- `npm run e2e`: Playwright smoke test (`e2e/`), screenshots → `e2e/screenshots/`
- `npm run build`: typecheck + prod build
- `npx tsx tools/fetch-osm.ts [zone] [osm|routes|stations|areas]`: download zone from Overpass into `data/raw/` (`<zone>.osm.json`, `.routes.json`, `.stations.json`, `.areas.json`; all by default; servers flaky, mirrors tried in order)
- `npx tsx tools/build-city.ts [zone]`: raw OSM + Copernicus DEM → `data/cities/<zone>.json` (zones in `tools/zones.ts`)
  DEM tile not in git (41 MB): `curl -o data/raw/copernicus-S01-W079.tif https://copernicus-dem-30m.s3.amazonaws.com/Copernicus_DSM_COG_10_S01_00_W079_00_DEM/Copernicus_DSM_COG_10_S01_00_W079_00_DEM.tif`
  Río Verde track needs tile S02-W079 (also 41 MB, not in git, `data/raw/*.tif` ignored): `curl -o data/raw/copernicus-S02-W079.tif https://copernicus-dem-30m.s3.amazonaws.com/Copernicus_DSM_COG_10_S02_00_W079_00_DEM/Copernicus_DSM_COG_10_S02_00_W079_00_DEM.tif`

## Conventions
- Chassis/physics space: +X forward, +Y up, +Z right. Heading 0 = facing +X.
- Physics code (`src/vehicle/bus.ts`, `src/physics/`) must not import three.js → stays testable in Node.
- All driving feel in `data/buses/*.json` (buses, plus AE86 car with `kind: "car"` and the container truck `kind: "truck"`, free roam + races only); tune there, not code (incl. `nitro`: extra accel + how far past top speed it pushes). Nitro tank rules (1.5 s full burn, burst needs half tank, refilled only by drifting, close calls, running reds, plus in race perfect launch + road pickups) = gameplay, in `src/gameplay/nitro.ts`.
- UI text Spanish (Quito slang welcome); code/comments English.
- Playwright uses manually downloaded Chrome at `~/.cache/qbus-chrome/` (CDN install times out) w/ SwiftShader WebGL.
- `window.__qbus` exposes game state in dev builds for e2e.
- City data, terrain, road graph, OSM import (bridges/underpasses, rapid transit, map edge, campus walls, far view): see `src/world/CLAUDE.md`.
- Settings (`src/menu/settings.ts`) carry version: default changes → bump it, decide what old saved value means (version 2: saved 1.3 hills was old default → becomes new one, "Reales").
- Menus (`src/menu/`): `/` shows title/setup menu; game starts only with `?play=1` (from menu) or direct `?city=`/`?seed=`. Choices/settings in localStorage (`settings.ts`). Buses listed in `src/vehicle/buses.ts`; every preset must pass `tests/bus.test.ts`. Routes from `routesFor(city)` (`src/gameplay/routes.ts`).
- Navigation (`src/gameplay/navigation.ts`): Dijkstra over directed lane graph → guidance + route building respect one-ways. `new Navigator(graph, vehicle = 'general', generalCost = 1)`: ordinary vehicles never use busway edge (`Road.access === 'brt'`, see `src/world/CLAUDE.md`), `'brt'` vehicles may (rapid-transit routes, `BRT_GENERAL_COST` = 3 so they follow busway whenever one exists; route/leg lengths real meters via `pathMeters`, not weighted cost). BRT lines (Trolebús C4, also stands for C1 w/ same stations, Ecovía E1/E3; MetroBus only two stations in zone, 4 stops, too few for route) start loop at first stop served from busway lane; `startPose` snaps with `vehicle: 'brt'` so bus starts on busway; ordinary routes + free roam never use or get guided onto one. In-game arrow + minimap follow legal path (`session.path`), never straight line to stop. Routes keep only stops whose legs drivable legally w/o big detours. Menu map draws each leg's legal path (`routePaths`); bus starts on lane leading into first stop, facing it (`startPose`, via `Navigator.behind`). Where roads overlap, everything located at height: `locate(p, heading, y)` (stops at street level, bus at `BusPhysics.roadHeight()`, wheels' contact height), paths carry each point's lift so arrow (`guidePoint(..., lift)`) never follows street over bus's underpass, and R reset (`snapToRoad(..., y, { clear: vehicleClearance(world, body), length })`) stays on bus's level, slides to spot where bus box clears static world, pitched to road.
- Map data ODbL: keep on-screen OpenStreetMap credit (`city.attribution`).
- Names/credits: real streets, places, transit systems (Trolebús, Ecovía, Metro) plain text only; real companies never. Bus operators get look-alike name at import (`src/world/osm/operators.ts`, "Catar" → "Katar"; add new operators there, `tests/operators.test.ts` checks none leak into city data), car = "Toyoya Sprinta Trueno AE86", truck = tractor maker "Taitar", Metro totems carry own pictogram (not city's "M" logo), shop signs invented. Menu's "Créditos" screen holds OSM/ODbL, full Copernicus, sound/music credits + non-affiliation notice: update when adding data, sounds, names.
- Headless Chrome = software WebGL (~5–20 fps), slows sim (frame dt capped 0.1 s). In e2e poll conditions (`expect.poll`), no fixed sleeps.
- BRT buses + menu: picking Trolebús/Ecovía route selects articulated bus (`BRT_BUS`, `busForRoute` in `menu.ts`: unless player hand-picked another bus for BRT routes; back to ordinary route restores replaced bus; saved settings not overridden at load); placard says "Carril exclusivo · Recomendado: Articulado". Any bus may drive any route; link to BRT route w/o `?bus=` takes articulated. Non-BRT vehicle on busway not punished: HUD street label already reads "Carril exclusivo". Tutorial adds line on BRT routes.
- Traffic/pedestrians: ambient articulated buses (`BRT_KIND`, 18 m, 3 instanced meshes' worth in `trafficView.ts`: two box sections + bellows) ride busway lanes only (`TrafficSim` option `brt`, `brtBusCount`: 1 per ~1.2 km busway, 1–4, 0 w/o busway; outside `setBudget`); straight on only (turn would swing rigid 18 m box over street beside), stop 5 s at station (`stations`: stop zones beside busway edge facing its way), keep junction claimed until tail clears (`tail`), ignore oncoming busway bus (other lane), share junction with straight movements along own axis (`straight`/`parallel` in `canEnter`: avenue beside busway, oncoming bus) only where two paths stay a bus + buseta apart for 20 m out (`clearOf`; busway leaving junction a lane from avenue's near lane doesn't share), else two buses nose to nose wait on each other forever; claim junctions their busway runs through w/o meeting them (`Crossing`: OSM draws Ecovía across side street's junction w/ 6 de Diciembre w/ no shared node; bus stops short until only straight traffic alongside in it, holds until tail out, cars wait for it like any car in junction), obey lights, at a busway end wait `TERMINAL_DWELL` 4 s then swing round onto the lane back (`terminal`/`turnRound`: within 40 m, claims the junction like any turn, waits for its green; no lane near: such busway edges are `traps`, buses never spawn on or drive into them), become wrecks when hit. Ordinary cars never use busways. `traffic.ts` + `pedestrians.ts` pure sims (unit-tested for overlaps + gridlock on both cities); `trafficBodies.ts` makes Rapier bodies chase sim poses (height/pitch from terrain), releases car to free physics when bus hits it. Junctions admit one incoming edge at a time; no forced entry (stuck cars recycled). Car never claims junction while queued behind car on same approach that hasn't (one in next lane whose path merges into ours: w/ our claim it may not go in, we can't pass it); car held back by short exit's next junction (`after.len` < 25 m) claims priority there too after `PRIORITY_WAIT`, else busy stream through it starves short exit's feeders (Queseras tunnel link behind Queseras' 16 m). Traffic lights (`gameplay/trafficLights.ts`, pure, tested; `TrafficLights` from `city.signals` + road graph): junction lit if signal at its level on paved area or up to 15 m out an approach; incoming edges grouped into phases by approach axis (opposites together), each phase green 14 s (10 s w/ 3+ phases), amber 3 s, then 2 s all red; per-junction offsets from position, but junctions within 60 m share timing + give widest road first phase (divided avenue's two crossings). All function of traffic clock (`TrafficSim.time`). Cars stop bumper at stop line (4 m before edge end, behind zebra) on red, and on amber if able at 3.5 m/s²; car waiting at light, or queued behind one that is (`Car.held`), neither claims junction priority nor counts toward `STUCK_WAIT`; priority claim lapses while approach not green. Pedestrians at lit crossing wait at curb for crossed approach's red. `world/signalBuilder.ts` draws pole on right curb at each stop line w/ arm over incoming lanes + three-lamp head (static tiles, solid pole), lamps one instanced mesh whose instance colors change w/ lights (+ additive glow mesh after dark: no real lights), and stop line. Pedestrians walk sidewalk strips derived from road graph, no colliders by design. In-lane traffic in collision group TRAFFIC, ignores STATIC world (`markStatic` in `physics/world.ts`, called end of `buildCity`): sim keeps cars on road, so ramp/wall seams can't knock them off; car hit by bus → wreck colliding w/ everything (`tests/interchanges.test.ts` runs traffic through both interchanges). Cars ride road's own surface (`laneSurface`: `surfaceY`, near bridges/cuts solid surface under them via short STATIC ray), placed on it from first frame. Obstacles carry `lift` (height off ground): things on another level (street over underpass) don't hold car up; pedestrians avoid open cut edges.
- Passengers board/alight when bus in stop zone under 25 km/h (`STOP_SPEED` in `routeGame.ts`): Quito bus barely stops.
- Scores + missions (route shifts only, pure modules): `gameplay/stars.ts` sets each route's 1–3 star money targets from model drivers (`STAR_TIERS`: door-to-door pace 10/14/16.5 m/s along legal legs, `routeLegs`, through real `RouteGame` rules, + trick money 0/0.75/5 cents per shift second (autopilot runs every red it meets) + 0/1/2 avg mission bonuses) → routes w/ long legs or detours ask less fare money. 1★ = steady clean shift, 2★ = quick w/ some tricks + mission, 3★ = expert (beyond autopilot). Paces from `tools/sim-shift.ts` (autopilot driving real physics bus through shifts: casual/decent/expert); BRT routes (any stop with `system`): busway legs of 500-1000 m run out the 90 s clock at 10 m/s, so their model drivers drive at least the pace that serves 2/3/4 stops (`BRT_SERVED`, capped 18 m/s) and floors are 2/4/7 dollars (`BRT_FLOOR`): 1★ never from red-run tricks alone (C4 3.30/7.75/15.90, E3 2.00/6.65/14.50, E1 2.00/4.00/7.75; autopilot BUS=articulado ends them in 1-4 stops, pins use it). `tests/stars.test.ts` pins its earnings so autopilot never gets 3★ (except Belavista 002's long straight avenues); `tools/star-targets.ts` prints every route's targets. Targets shown on start prompt, as meter beside money (stars won + money for next), ticked on results screen + each menu placard. `gameplay/records.ts` keeps top 5 per `zone/route` (any bus; bus noted), best stars, mission completion counts in localStorage `qbus.records` (versioned; corrupt data dropped, never thrown; version 1 records keep money, lose stars earned vs old easy targets; placards + top 5 rate saved money vs today's targets). `gameplay/missions.ts` = pool of optional objectives (3 random per shift, cash bonus each), fed `MissionEvent`s by `GameSession`; only build missions on events game reliably detects. Running red (`RedLightRunner`: bus front bumper crossing stop line into junction while approach red, amber doesn't count, at light's level, once per junction + cycle; route shifts + free roam) = trick "¡Pasó en rojo!" (20 cents, joins combos), refills quarter nitro tank, honks drivers, counts for "Pásate 3 rojos" mission. - Third track "Bajada de Río Verde" (`rioverde`, E30 Ruta de las Cascadas Baños–Puyo, Pastaza gorge, 6.9 km raced from a bridge by Río Pastaza to 180 m past Túnel Chirosinguna, DEM tile S02-W079): zone `track` takes `biome: 'canyon'` + `structures: true` (OSM `tunnel`/`bridge` ways become `race.tunnels` / `race.bridges`; absent on the first two tracks, whose JSON must stay byte-identical: check `git diff data/cities` after rebuilding them). Canyon biome (`world/biomes.ts`: grey-brown rock cliffs from slope 0.55/0.85 (`cliff`), subtropical green, tree ferns + bamboo, thin mist; `SHAPING.canyon`: the DEM's own steep fall plus a bounded extra `bench` of 16 m near the road, 1.25 fill bank; a multiple of the DEM's depth made a knife-cut trench beside the rail then a wall): only ~1/4 of drops railed (`OPEN.canyon`, rails dropped at random after the usual pass, never in the safe zones). Road height over tunnels/bridges is the straight line between their ends (the DEM there is mountain/gully). **Tunnels** (`world/tunnels.ts`, `race.tunnels` `{s0,s1,top[]}`, `top` = mountain over the deck every 12 m, from the DEM): the heightfield stays the road's ordinary cut (lowered under the deck across the bore, `BORE_HALF` 5.4), so ground logic (fall watch, off-road, R reset, ghost, plants, `locateOnTrack`) never sees a tunnel; the closed bore is its own mesh: rough rock arch + walls (`boreRing`, outward-only roughness, never inside the swept space), unlit `MeshBasicMaterial` with the lamp pools + daylight spill baked into vertex colors, instanced lamp fittings, a rock **mound** ribbon (`moundHeight`: climbs 0.75/m from each portal up to the DEM, blends into the cut ground at `MOUND_HALF` 18 m) with concrete-framed portal faces. Bore and mound are trimesh colliders (smooth, frictionless bore walls): with `FIX_INTERNAL_EDGES` Rapier trimeshes are ONE-SIDED (solid behind the winding normals), so bore triangles are wound to face into the bore (`inward`) and the mound's face up, else a bus drives through the wall. - Vehicle collisions (`physics/bump.ts`, Rapier only, `tests/collision.test.ts` + `tests/netBump.test.ts`): plastic Rapier contacts + kinematic remotes (infinite mass) made rear-ending a dead stop. Now `BumpTracker` (in `RaceSession`; `bumpBefore`/`bumpAfter` around `world.step()` in `main.ts`) treats a vehicle-vehicle hit as two-body collision: `bumpImpulse(m1, m2, closing)` = `(1+e)` x closing x reduced mass (`BUMP.restitution` 0.45, nudges under `minClosing` ignored, never more than `maxDv` 14 m/s on lighter one), x `sideGain` (1.6 for broadside: tires scrub sideways shove away, `BusPhysics.bumpSlide` loosens them 0.6 s after one). Masses = `BusPhysics.totalMass`. `BusPhysics.shove(j, at)` applies it (same velocity change on every section + capped yaw spin from off-center point, no vertical). Two local dynamic vehicles (player, AI): Rapier still solves contact, tracker adds only the bounce (closing speed from velocities before the step). Local vs remote: remote colliders have `REMOTE_SOLVER` groups (`world.ts`; vehicles `VEHICLE_SOLVER`; contacts detected, no force; solver groups must be unsigned `>>> 0` or Rapier sets 0), tracker computes whole hit from `RemoteBus.vel` (measured from poses), applies our share, `RemoteBus.shove` moves its proxy ahead at once (0.4 s, fades 0.6 s while real shove shows in snapshots) and sends its share as `bump {from, to, j:[x,z], at}` (C2S/S2C, optional, `Bump` in `protocol.ts`; `RoomLogic.bump` relays to seat that simulates `to`, host for an AI, only while racing, sender's own bus, `BUMPS_PER_SEC` 20). Receiver applies it (`receiveBump`) to its own bus; each client sees hit from own view, a pair is quiet `BUMP.cooldown` 0.5 s after a bump applied or received, so nothing counts twice. Ghosts (either side) never bump. Traffic wrecks, train self-collision filtering unchanged.
