# QBus

Arcade "Crazy Taxi"-style game: drive reckless Quito bus, pick up passengers at stops.
Browser game: Three.js (rendering) + Rapier (`@dimforge/rapier3d-compat`, physics), TypeScript, Vite.
Full roadmap (M0–M6): `~/.claude/plans/pasted-content-id-88c6-i-want-synchronous-wren.md`.

## Commands
Node from nvm: run `. ~/.nvm/nvm.sh` first in non-login shells.
- `npm run dev`: dev server on http://localhost:5173
- `npm test`: Vitest unit tests (`tests/`), physics headless in Node
- `npm run test:underpass`: bridge/underpass harness, slow physics suites included (`tests/underpass/README.md`)
- `npm run e2e`: Playwright smoke test (`e2e/`), screenshots → `e2e/screenshots/`
- `npm run build`: typecheck + prod build
- `npx tsx tools/fetch-osm.ts [zone] [osm|routes|stations|areas]`: download zone from Overpass into `data/raw/` (`<zone>.osm.json`, `.routes.json`, `.stations.json`, `.areas.json`; all by default; servers flaky, mirrors tried in order)
- `npx tsx tools/build-city.ts [zone]`: raw OSM + Copernicus DEM → `data/cities/<zone>.json` (zones in `tools/zones.ts`)
  DEM tile not in git (41 MB): `curl -o data/raw/copernicus-S01-W079.tif https://copernicus-dem-30m.s3.amazonaws.com/Copernicus_DSM_COG_10_S01_00_W079_00_DEM/Copernicus_DSM_COG_10_S01_00_W079_00_DEM.tif`

## Conventions
- Chassis/physics space: +X forward, +Y up, +Z right. Heading 0 = facing +X.
- Physics code (`src/vehicle/bus.ts`, `src/physics/`) must not import three.js → stays testable in Node.
- All driving feel in `data/buses/*.json` (buses, plus AE86 car with `kind: "car"`, free roam only); tune there, not code (incl. `nitro`: extra accel + how far past top speed it pushes). Nitro tank rules (1.5 s full burn, burst needs half tank, refilled only by drifting, close calls, running reds, plus in race perfect launch + road pickups) = gameplay, in `src/gameplay/nitro.ts`.
- UI text Spanish (Quito slang welcome); code/comments English.
- Playwright uses manually downloaded Chrome at `~/.cache/qbus-chrome/` (CDN install times out) w/ SwiftShader WebGL.
- `window.__qbus` exposes game state in dev builds for e2e.
- City data, terrain, road graph, OSM import (bridges/underpasses, rapid transit, map edge, campus walls, far view): see `src/world/CLAUDE.md`.
- Settings (`src/menu/settings.ts`) carry version: default changes → bump it, decide what old saved value means (version 2: saved 1.3 hills was old default → becomes new one, "Reales").
- Menus (`src/menu/`): `/` shows title/setup menu; game starts only with `?play=1` (from menu) or direct `?city=`/`?seed=`. Choices/settings in localStorage (`settings.ts`). Buses listed in `src/vehicle/buses.ts`; every preset must pass `tests/bus.test.ts`. Routes from `routesFor(city)` (`src/gameplay/routes.ts`).
- Navigation (`src/gameplay/navigation.ts`): Dijkstra over directed lane graph → guidance + route building respect one-ways. `new Navigator(graph, vehicle = 'general', generalCost = 1)`: ordinary vehicles never use busway edge (`Road.access === 'brt'`, see `src/world/CLAUDE.md`), `'brt'` vehicles may (rapid-transit routes, `BRT_GENERAL_COST` = 3 so they follow busway whenever one exists; route/leg lengths real meters via `pathMeters`, not weighted cost). BRT lines (Trolebús C4, also stands for C1 w/ same stations, Ecovía E1/E3; MetroBus only two stations in zone, 4 stops, too few for route) start loop at first stop served from busway lane; `startPose` snaps with `vehicle: 'brt'` so bus starts on busway; ordinary routes + free roam never use or get guided onto one. In-game arrow + minimap follow legal path (`session.path`), never straight line to stop. Routes keep only stops whose legs drivable legally w/o big detours. Menu map draws each leg's legal path (`routePaths`); bus starts on lane leading into first stop, facing it (`startPose`, via `Navigator.behind`). Where roads overlap, everything located at height: `locate(p, heading, y)` (stops at street level, bus at `BusPhysics.roadHeight()`, wheels' contact height), paths carry each point's lift so arrow (`guidePoint(..., lift)`) never follows street over bus's underpass, and R reset (`snapToRoad(..., y, { clear: vehicleClearance(world, body), length })`) stays on bus's level, slides to spot where bus box clears static world, pitched to road.
- Map data ODbL: keep on-screen OpenStreetMap credit (`city.attribution`).
- Names/credits: real streets, places, transit systems (Trolebús, Ecovía, Metro) plain text only; real companies never. Bus operators get look-alike name at import (`src/world/osm/operators.ts`, "Catar" → "Katar"; add new operators there, `tests/operators.test.ts` checks none leak into city data), car = "Toyoya Sprinta Trueno AE86", Metro totems carry own pictogram (not city's "M" logo), shop signs invented. Menu's "Créditos" screen holds OSM/ODbL, full Copernicus, sound/music credits + non-affiliation notice: update when adding data, sounds, names.
- Headless Chrome = software WebGL (~5–20 fps), slows sim (frame dt capped 0.1 s). In e2e poll conditions (`expect.poll`), no fixed sleeps.
- BRT buses + menu: picking Trolebús/Ecovía route selects articulated bus (`BRT_BUS`, `busForRoute` in `menu.ts`: unless player hand-picked another bus for BRT routes; back to ordinary route restores replaced bus; saved settings not overridden at load); placard says "Carril exclusivo · Recomendado: Articulado". Any bus may drive any route; link to BRT route w/o `?bus=` takes articulated. Non-BRT vehicle on busway not punished: HUD street label already reads "Carril exclusivo". Tutorial adds line on BRT routes.
- Traffic/pedestrians: ambient articulated buses (`BRT_KIND`, 18 m, 3 instanced meshes' worth in `trafficView.ts`: two box sections + bellows) ride busway lanes only (`TrafficSim` option `brt`, `brtBusCount`: 1 per ~1.2 km busway, 1–4, 0 w/o busway; outside `setBudget`); straight on only (turn would swing rigid 18 m box over street beside), stop 5 s at station (`stations`: stop zones beside busway edge facing its way), keep junction claimed until tail clears (`tail`), ignore oncoming busway bus (other lane), share junction with straight movements along own axis (`straight`/`parallel` in `canEnter`: avenue beside busway, oncoming bus) only where two paths stay a bus + buseta apart for 20 m out (`clearOf`; busway leaving junction a lane from avenue's near lane doesn't share), else two buses nose to nose wait on each other forever; claim junctions their busway runs through w/o meeting them (`Crossing`: OSM draws Ecovía across side street's junction w/ 6 de Diciembre w/ no shared node; bus stops short until only straight traffic alongside in it, holds until tail out, cars wait for it like any car in junction), obey lights, wait out of sight at busway end + recycle like cars, become wrecks when hit. Ordinary cars never use busways. `traffic.ts` + `pedestrians.ts` pure sims (unit-tested for overlaps + gridlock on both cities); `trafficBodies.ts` makes Rapier bodies chase sim poses (height/pitch from terrain), releases car to free physics when bus hits it. Junctions admit one incoming edge at a time; no forced entry (stuck cars recycled). Car never claims junction while queued behind car on same approach that hasn't (one in next lane whose path merges into ours: w/ our claim it may not go in, we can't pass it); car held back by short exit's next junction (`after.len` < 25 m) claims priority there too after `PRIORITY_WAIT`, else busy stream through it starves short exit's feeders (Queseras tunnel link behind Queseras' 16 m). Traffic lights (`gameplay/trafficLights.ts`, pure, tested; `TrafficLights` from `city.signals` + road graph): junction lit if signal at its level on paved area or up to 15 m out an approach; incoming edges grouped into phases by approach axis (opposites together), each phase green 14 s (10 s w/ 3+ phases), amber 3 s, then 2 s all red; per-junction offsets from position, but junctions within 60 m share timing + give widest road first phase (divided avenue's two crossings). All function of traffic clock (`TrafficSim.time`). Cars stop bumper at stop line (4 m before edge end, behind zebra) on red, and on amber if able at 3.5 m/s²; car waiting at light, or queued behind one that is (`Car.held`), neither claims junction priority nor counts toward `STUCK_WAIT`; priority claim lapses while approach not green. Pedestrians at lit crossing wait at curb for crossed approach's red. `world/signalBuilder.ts` draws pole on right curb at each stop line w/ arm over incoming lanes + three-lamp head (static tiles, solid pole), lamps one instanced mesh whose instance colors change w/ lights (+ additive glow mesh after dark: no real lights), and stop line. Pedestrians walk sidewalk strips derived from road graph, no colliders by design. In-lane traffic in collision group TRAFFIC, ignores STATIC world (`markStatic` in `physics/world.ts`, called end of `buildCity`): sim keeps cars on road, so ramp/wall seams can't knock them off; car hit by bus → wreck colliding w/ everything (`tests/interchanges.test.ts` runs traffic through both interchanges). Cars ride road's own surface (`laneSurface`: `surfaceY`, near bridges/cuts solid surface under them via short STATIC ray), placed on it from first frame. Obstacles carry `lift` (height off ground): things on another level (street over underpass) don't hold car up; pedestrians avoid open cut edges.
- Passengers board/alight when bus in stop zone under 25 km/h (`STOP_SPEED` in `routeGame.ts`): Quito bus barely stops.
- Scores + missions (route shifts only, pure modules): `gameplay/stars.ts` sets each route's 1–3 star money targets from model drivers (`STAR_TIERS`: door-to-door pace 10/14/16.5 m/s along legal legs, `routeLegs`, through real `RouteGame` rules, + trick money 0/0.75/5 cents per shift second (autopilot runs every red it meets) + 0/1/2 avg mission bonuses) → routes w/ long legs or detours ask less fare money. 1★ = steady clean shift, 2★ = quick w/ some tricks + mission, 3★ = expert (beyond autopilot). Paces from `tools/sim-shift.ts` (autopilot driving real physics bus through shifts: casual/decent/expert); `tests/stars.test.ts` pins its earnings so autopilot never gets 3★ (except Belavista 002's long straight avenues); `tools/star-targets.ts` prints every route's targets. Targets shown on start prompt, as meter beside money (stars won + money for next), ticked on results screen + each menu placard. `gameplay/records.ts` keeps top 5 per `zone/route` (any bus; bus noted), best stars, mission completion counts in localStorage `qbus.records` (versioned; corrupt data dropped, never thrown; version 1 records keep money, lose stars earned vs old easy targets; placards + top 5 rate saved money vs today's targets). `gameplay/missions.ts` = pool of optional objectives (3 random per shift, cash bonus each), fed `MissionEvent`s by `GameSession`; only build missions on events game reliably detects. Running red (`RedLightRunner`: bus front bumper crossing stop line into junction while approach red, amber doesn't count, at light's level, once per junction + cycle; route shifts + free roam) = trick "¡Pasó en rojo!" (20 cents, joins combos), refills quarter nitro tank, honks drivers, counts for "Pásate 3 rojos" mission. If scoring, fares, time bonuses or missions change → rerun `tools/sim-shift.ts`, retune `STAR_TIERS`.
- Free roam (`?play=1&mode=free&city=&bus=`): `GameSession` w/ `route: null` (`game` null): traffic, people, nitro; no stops, clock, fares, trick money; starts at `freeStartPose`. Menu's "Paseo libre" offers `VEHICLES` (buses + `CARS`); route shift always bus. Cars have own model (`vehicle/carBody.ts`) + `cockpit.seat` in preset.
- Articulated bus (`data/buses/articulado.json`, `preset.articulated`, "Articulado BRT", 18.4 m, any route + free roam; gusanito = same machinery w/ 4 rear sections): `BusPhysics` makes two Rapier bodies, each own raycast vehicle (front: steered axle + driven middle axle; rear: one trailing axle), hinged by ball joint at turntable, inter-section contacts off; joint motors (set via raw joint set, since rapier3d-compat 0.20 gives spherical joint no JS motor API) hold roll + push back past `yawLimitDeg`. Chosen over kinematic trailer by `tools/spike-articulated.ts` (trailer drives through walls reversing, 3.4 m deep). `body` = front section; rest of game must go through `bus.position()` (middle of whole vehicle: stops, traffic, R reset, minimap), `bus.nose()`, `bus.sections()` (one traffic obstacle box per section), `bus.colliders`/`bus.bodies` (hits on either section wreck car; near-miss rays from both; reset places both in line, `Spawn` x/z = vehicle middle), `bus.frontLength` (cockpit seat + doors in front section), `bus.wheelCount`. Section ends chamfered (`bevel`): plain 9 m box high-centers where ramp flattens. Handbrake drifts arcade-assisted (`driftLock` freezes turntable, `driftYawRate` pushes yaw + fades near `drift.maxAngleDeg`, `driftFrontGrip` loosens front tires) so front-section slip passes 20° for >1 s and scores; `tools/sim-shift.ts` (`BUS=articulado`) steers by `nose()`; `position()`/`nose()` take `out` object for per-frame callers. Covered by `tests/bus.test.ts` (articulated block), `tests/articulated.city.test.ts`, underpass harness (`DRIVE.RUNS`; known failure `Q1A`). Model has doors both sides (left for BRT platforms) + bellows.
- El Gusanito (`data/buses/gusanito.json`, any route + free roam, never traffic): fairground "worm" train, worm-faced head car pulling 4 open wagons under striped canopies (`articulated.sections` = 4: `BusPhysics.rears` is chain, each wagon hinged to one ahead w/ one trailing axle; `bendAt(i)` per turntable, `bus.rear` = first). Sections share own collision bit (`GROUP.TRAIN << k`, one per train, `physics/world.ts`), filtered out (another gusanito, race rival, is solid), wheel rays skip it: on tight bend wagon swings into box of one two ahead. Train folds in reverse → `reverseLock` pulls turntables straight while backing (reverses like rigid bus); no `driftLock` (head car drifts, wagons whip behind), stiffer yaw limit (`yawLimitStiffness`: light wagons swing past it in crash). Model in `vehicle/gusanitoBody.ts` (eyes, lips, antennae, riders, LED strips glowing at night, spiral tail), cockpit w/o windshield + eyes; riders board at first wagon (`passengersView`); car engine sound, no door hiss (`isTrain`).
- Rain (`gameplay/weather.ts`, pure, tested; Ajustes "Lluvia": `random` (default: shower starts 25–200 s in, then random-strength showers + dry spells), `always`, `off`; `?rain=0|1|2` overrides: never, raining, downpour): `Weather.state` = `rain` (0..1), `wet` (road: wets fast, dries ~90 s), `flood` (m: only rain over `DOWNPOUR` 0.7 fills underpasses, up to 0.75 m, drains after). Grip: `bus.grip = gripFor(wet)`; wet road caps tires' `frictionSlip` at preset's `wet: { front, rear }` (tuned per vehicle w/ `tools/wet-grip.ts` to slide 10–16° at full lock at speed, 3–8° dry; articulado never reaches limit, only brakes longer), brakes 30% weaker. Rapier raycast tires cancel all sideways speed each step → scaling correction/friction proportionally does nothing: only absolute cap under what turn needs slides. Floods: `world/floods.ts` finds each underpass basin (cut roads w/ floors at ~same height share one), draws water as one opaque mesh raised by flood depth; `waterDepth` sets `bus.wade`, drag (+ lost grip past 0.15 m) holds bus to crawl (nitro still pushes), spray off wheels (`BusModel.setSpray`); traffic crawls (3.5 m/s) through flooded lanes (`TrafficSim.slowEdges`), 15% slower on wet road (`speedScale`). `world/rain.ts` (`RainView`): streaks around camera moved in vertex shader (one draw call), faded under roof (upward static ray from camera), sky/fog/lights overcast (city + backdrop), lightning + thunder in downpour; synthesized rain, splash, thunder sounds (`BusAudio.weather`/`thunder`, `LEVELS`). Passenger + popup announce rain + floods (`session.weatherNews`).

- Ghost after a respawn (`gameplay/ghost.ts`, races): after R, a fall or an AI rescue a bus collides only with the static world for `GHOST_TIME` (after the R hold), drawn see-through (`BusModel.setGhost`); still overlapping a vehicle at the end it stays a ghost up to `GHOST_MAX`, then moves to the nearest free spot on the road. Online the snapshot carries it (`g`). Adaptive quality (`core/adaptiveQuality.ts`, pure, tested; wired in `main.ts`): smoothed fps under 38 for 2 s → canvas pixel ratio steps down (levels 1, 0.85, 0.72, 0.6 of usual cap); lowest level still under 28 fps → shadow map drops to 1024; steps back up after 10 s over 57 fps unless that level just failed. Each step down judged after 3 s: if smoothed fps didn't rise 10% (`MIN_GAIN`: 30 Hz display, battery-saver cap, or CPU-bound machine) step undone + stepping down (and shadow shrinking) disabled for session. 60 fps machines never leave level 0. Off under automation (`navigator.webdriver`) unless `?adaptive=1`, off w/ `?adaptive=0` (`e2e/adaptive.spec.ts`).
